# Generating import data (agent guide)

Produce one flat sheet named `Transactions` using the exact headers from `storage/paytrack_transactions_template.xlsx`: `type, transaction_id, transaction_date, channel, payment_mode, amount, currency, payer_name, payer_phone, reference, expected_amount, rate, charges, settled_amount, status`. One row per payment. `type` is `money_in` or `money_out`; `transaction_id` must be unique per type (it is how re-uploads are de-duplicated); `transaction_date` is `YYYY-MM-DD HH:MM:SS`; `channel` is the channel/outlet name (created if new); `payment_mode` is `mpesa`, `cash`, `card` or `bank`; numbers are plain (no commas or currency symbols). `amount` is what the client paid, `expected_amount` is what they should have paid (leave blank if unknown, since any difference of 1 or more raises an exception), and `reference` is the invoice/receipt/bank reference.

Money settled to the merchant needs only ONE of `rate` (%), `charges` (actual fee) or `settled_amount` (amount minus fee). Fill whichever the source gives you and leave the rest blank, because the system computes the others (`charges = amount - settled_amount`, `rate = charges / amount x 100`). Only fill more than one if they agree exactly (`settled_amount + charges = amount`), or the row is rejected. Leave all three blank to use the channel's configured rate. Never invent values: leave a cell blank when the source does not have it, keep money-out rows free of rate/charges/settled, and deliver `.xlsx` (or `.csv`) with no extra sheets or merged cells in `Transactions`.
